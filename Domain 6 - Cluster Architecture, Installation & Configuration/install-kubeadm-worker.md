#### Step 1: Setup containerd

This step enables the required kernel modules and networking settings for containerd so that Kubernetes pods can run correctly on the worker node. The `overlay` filesystem is used by containerd, and `br_netfilter` allows bridge traffic to pass through iptables rules required by Kubernetes networking.

```sh
cat <<EOF | sudo tee /etc/modules-load.d/containerd.conf
overlay
br_netfilter
EOF
```

```sh
sudo modprobe overlay
sudo modprobe br_netfilter
```

```sh
cat <<EOF | sudo tee /etc/sysctl.d/99-kubernetes-cri.conf
net.bridge.bridge-nf-call-iptables  = 1
net.ipv4.ip_forward                 = 1
net.bridge.bridge-nf-call-ip6tables = 1
EOF
```

```sh
sudo sysctl --system
```

```sh
sudo apt-get update
sudo apt-get install -y containerd
sudo mkdir -p /etc/containerd
containerd config default | sudo tee /etc/containerd/config.toml
```

```sh
sudo nano /etc/containerd/config.toml
```

Set the following value to `true`:

```toml
SystemdCgroup = true
```

This config ensures containerd uses systemd as the cgroup driver, which is required by kubelet and Kubernetes components.

```sh
sudo systemctl restart containerd
sudo systemctl enable containerd
```

#### Step 2: Kernel Parameter Configuration

This step applies the required Linux kernel parameters for Kubernetes networking. These settings ensure that bridge traffic is processed correctly by iptables for pod communication and cluster networking.

```sh
cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-ip6tables = 1
net.bridge.bridge-nf-call-iptables = 1
EOF
```

```sh
sudo sysctl --system
```

#### Step 3: Configuring Repo and Installation

This step adds the official Kubernetes package repository and installs the required components on the worker node: `kubeadm`, `kubelet`, `kubectl`, and `cri-tools`. These tools are needed to join the node to the cluster and run container workloads.

```sh
sudo apt-get update
sudo apt-get install -y apt-transport-https ca-certificates curl gpg
```

```sh
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.32/deb/Release.key | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg

echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.32/deb/ /' | sudo tee /etc/apt/sources.list.d/kubernetes.list
```

```sh
sudo apt-get update
apt-cache madison kubeadm
sudo apt-get install -y kubelet=1.32.0-1.1 kubeadm=1.32.0-1.1 kubectl=1.32.0-1.1 cri-tools=1.32.0-1.1
sudo apt-mark hold kubelet kubeadm kubectl
sudo systemctl enable --now kubelet
```

> Note: Use the version shown by `apt-cache madison kubeadm` if a newer patch version is available.

#### Step 4: Join Worker Node

This is the actual step where the worker node connects to the Kubernetes control plane. The `kubeadm join` command contains the cluster address, token, and CA certificate hash generated by the master node. Without this command, the worker cannot authenticate and join the cluster.

Run the exact `kubeadm join` command generated on the master/control-plane node. The command below is only for reference.

```sh
sudo kubeadm join 209.38.120.248:6443 --token 9vxoc8.cji5a4o82sd6lkqa \
  --discovery-token-ca-cert-hash sha256:1818dc0a5bad05b378dd3dcec2c048fd798e8f6ff69b396db4f5352b63414baf
```

If the join token has expired, generate a new one on the control-plane node:

```sh
kubeadm token create --print-join-command
```

#### Step 5: Verification (Run on the Master/Control Plane Node)

After the worker is joined, this step verifies whether the node successfully registered with the cluster and is healthy. The `Ready` status confirms that the worker is connected, running the kubelet, and able to accept workloads.

```sh
kubectl get nodes
```

Example output:

```sh
NAME        STATUS   ROLES    AGE   VERSION
worker-1    Ready    <none>   2m    v1.32.0
```

#### Troubleshooting

If the node is not ready, check the kubelet logs to identify join or runtime issues:

```sh
sudo journalctl -u kubelet -f
```

If `containerd` is failing, verify the configuration:

```sh
sudo containerd config dump
```
